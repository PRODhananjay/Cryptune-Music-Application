# Cryptune Terraform Infrastructure

This Terraform project provisions the AWS production architecture for Cryptune.

## What it creates

- VPC across 2 Availability Zones
- Public subnets for ALB + NAT Gateways
- Private app subnets for ECS Fargate
- Private DB subnets for RDS PostgreSQL Multi-AZ
- ECR repositories for frontend/backend
- ECS Fargate cluster/service
- Application Load Balancer
- AWS WAF
- Secrets Manager
- CloudWatch Logs + ECS Container Insights
- VPC Flow Logs
- CloudTrail
- CodePipeline + CodeBuild
- S3 pipeline artifact bucket
- Optional S3 remote Terraform state bootstrap

Cloudinary remains the external media store for M4A files and cover images.

## Important

Terraform creates infrastructure. It does not store your music in AWS S3 and it does not need to run for every application deployment.

The ECS task uses the images in ECR. The first CodePipeline run builds/pushes the images and updates ECS.

The GitHub CodeConnections resource is created in PENDING state. You must authorize the GitHub connection in the AWS console once.

RDS Multi-AZ is one `aws_db_instance` resource. AWS manages the standby automatically; Terraform does not create a second RDS instance for the standby.

## Bootstrap

1. Copy `bootstrap/terraform.tfvars.example` to `bootstrap/terraform.tfvars`.
2. Choose a globally unique S3 state bucket name.
3. Run:

   terraform init
   terraform apply

4. Copy the output bucket name into `infra/backend.tf`.

Then configure `infra/terraform.tfvars` and run:

   terraform init
   terraform plan
   terraform apply

## Secrets

Do not commit `terraform.tfvars`.

The DB master password is generated by RDS and managed by Secrets Manager. The application secret stores JWT and Cloudinary credentials.

## Cost

This is a production-style architecture. NAT Gateways, ALB, ECS Fargate, RDS Multi-AZ, WAF, CloudTrail and build services can incur charges. Destroy the environment when it is not needed.
